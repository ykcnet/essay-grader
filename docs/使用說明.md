# 作文批閱使用說明

> 版本 0.1.0（M7＋Google Drive 外部 inbox＋成績寫回 Excel）｜ 適用 Windows 10 22H2 以上（x64）
>
> 作文批閱是 local-first 的桌機工具：資料庫就是你選的資料夾，程式不連網、不上傳、不埋 telemetry。批注、分數、名單、回饋單與統計都在本機完成。

---

## 1. 安裝版與 portable 的差異

安裝程式提供兩種形式：

| 形式 | 檔名 | 特性 |
|---|---|---|
| 安裝版 | `EssayGrader-0.1.0-Setup.exe` | 可選安裝路徑、建立桌面與開始功能表捷徑、可從「應用程式與功能」解除安裝 |
| 免安裝版 | `EssayGrader-0.1.0-Portable.exe` | 單一 exe，直接執行；適合放在隨身碟或沒有安裝權限的電腦 |

兩者功能相同，**資料庫都不會自動放在程式資料夾**。第一次使用都要自己選一個資料夾當資料庫。

- 安裝版與 portable 可以共存，但**不要同時開啟同一個資料庫**；程式有單一實例與 `.essay-grader.lock` 雙重保護。
- 設定與日誌會放在 Windows 使用者資料夾（`%APPDATA%\作文批閱`）。portable 不會把日誌寫在 exe 旁邊。
- 換電腦時，備份資料庫資料夾即可；程式本身重新安裝或複製 portable exe 都能延續使用。

### 系統需求

- Windows 10 22H2 或 Windows 11，x64。
- 建議 8 GB 記憶體；大量 2600px 掃描頁時記憶體約 300–500 MB。
- 不需要網路。只有第一次下載安裝檔或更新程式時需要。

## 2. 第一次開啟資料庫

1. 啟動「作文批閱」。
2. 按右上角「開啟資料庫」。
3. 選一個資料夾：
   - 新學期：建議建立新的空資料夾，例如 `D:\作文批閱\114-1`。
   - 既有資料：直接選原本的 `essay-grader-data` 或它的上層資料庫資料夾。
4. 選好後，左側會列出這個資料庫裡的班級。

資料庫資料夾的結構如下（資料夾名稱全 ASCII，中文只存在 JSON）：

```
114-1/
  C302-2025F/                 ← 班級
    class.json                ← 班名、教師、名單
    E20250107/                ← 作業
      assignment.json         ← 題目、量規、規則
      gradebook.json          ← 成績表欄位對應（有設定才存在）
      S07/                    ← 學生（座號）
        p1.jpg                ← 頁面圖片
        work.json             ← 批注、分數、總評
        S07_feedback.pdf      ← 匯出的回饋單
      _stats/                 ← 統計 CSV
      _gradebook/             ← 成績寫回的 CSV 備援
      _feedback/              ← 整班批次回饋單 PDF 與報告
      _inbox/                 ← 手機上傳暫存
```

### 資料庫鎖

開啟資料庫時會建立 `.essay-grader.lock`，記錄程式 pid 與電腦名稱。

- 同一台電腦若上次程式異常關閉，殘留的鎖會自動接手。
- 如果顯示「資料庫已被其他程式開啟」，請先關閉另一個視窗，或確認沒有另一個 portable 版本正在執行。
- 正常按「關閉資料庫」會釋放鎖；直接關閉程式也會嘗試釋放。

### 建議的存放位置

- 放在本機磁碟（例如 `D:\`）最穩定。
- 不要讓 OneDrive／Google Drive／Dropbox **即時同步**資料庫資料夾；同步衝突可能同時改寫 JSON。雲端只適合放**備份 zip**，或當作手機上傳用的外部 inbox（見 5.1）。
- 每個學期一個資料庫資料夾，避免同一資料夾累積多年資料。

## 3. 建立班級與作業

### 建立班級

1. 左側「班級」按「新增」。
2. 填班號、班名、年段（國中／高中／高職）、學年度、學期、教師。
3. 按「建立」。

班級資料夾會依「班號＋學年度＋學期」自動命名，例如 `C302-2025F`。同一個資料庫不能建立完全相同的班級代號。

### 建立作業

1. 先在左側選一個班級。
2. 在「作業」卡片按「新增」。
3. 填題目、題幹、截止日，選量規（均衡／內容導向／語言導向）。
4. 按「建立」。

作業資料夾依日期命名，例如 `E20261119`；同一天建立第二份會自動加 `-02`。

## 4. 以 Excel 匯入名單

1. 選好班級後，在名單卡片按「匯入 Excel」。
2. 選 `.xlsx` 檔。程式讀**第一個工作表**。
3. 前 10 列會自動尋找表頭：
   - 座號欄：標題含「座號」。
   - 姓名欄：標題含「姓名」或「名字」。
4. 找不到表頭時，會退回「A 欄座號、B 欄姓名，從第 1 列開始讀」。

規則：

- 座號會正規化成兩位數，例如 `7` → `07`。
- 新座號新增；同座號更新姓名；不會刪除 Excel 裡沒出現的舊學生。
- 空白姓名、無效座號會跳過並在結果提示。
- 匯入後記得按「儲存名單」。也可以直接在名單表格手動修改座號、姓名、在學狀態。

## 5. inbox 匯入

手機或掃描器把圖片放進作業的 `_inbox`，桌機會自動配對。最簡單的方式：

1. 選班級與作業。
2. 在匯入佇列按「開啟 inbox」。
3. 把圖片與 sidecar JSON 放進去，關閉資料夾後回到程式，watcher 會自動匯入。

檔名規則：圖片與 sidecar 使用同一個主檔名，例如：

```
S07__20261119-0900__001.jpg
S07__20261119-0900__001.json
```

sidecar 內容起碼要包含：

```json
{
  "schema_version": 1,
  "class_id": "C302-2025F",
  "assignment_id": "E20261119",
  "seat": "07",
  "seq": 1,
  "session_id": "20261119-0900",
  "captured_at": "2026-11-19T09:00:00+08:00"
}
```

配對與安全規則：

- 座號必須在班級名單中且在學，否則移到 `_unmatched`。
- 同 page 重複（相同圖片 hash）會跳過。
- 缺少 sidecar、sidecar 格式錯誤、指向其他班級或作業，都會移到 `_unmatched`，原檔不刪。
- 沒有手機時，可按「模擬 10 檔」產生測試資料，走同一條 watcher 流程。

匯入後，佇列會顯示每份作品的狀態：待批、批閱中、已批。

## 5.1 Google Drive 外部 inbox（手機上傳）

手機先把作文照片上傳到 Google Drive，桌機監看「本機同步資料夾」後自動匯入。**資料庫仍只放本機**；Google Drive 只經過 inbox，不存放資料庫、`work.json`、分數或總評。

### 事前準備

1. 在桌機安裝並登入 **Google Drive for desktop**（Google 雲端硬碟電腦版）。
2. 在 Google Drive 建立一個專門資料夾，例如「我的雲端硬碟／EssayGrader／inbox」。
3. 確認它在本機有對應路徑，例如 `G:\我的雲端硬碟\EssayGrader\inbox`。這個路徑可能因電腦與帳號而不同，程式不寫死磁碟代號。

### 設定與套用

1. 開啟資料庫，選一個班級與作業。
2. 在匯入佇列的「Google Drive inbox」區塊按「設定／變更」。
3. 用資料夾選擇器選取本機同步資料夾；設定會寫入 `settings.json`，重開程式仍保留。
4. 按「建立此作業資料夾」，程式會在外部根目錄建立 `<root>/<classId>/<assignmentId>/`。
5. 按「開啟資料夾」可直接到該位置上傳；按「清除」會停止外部監看並移除設定。

設定或清除後立即套用，不需要重開程式。按匯入佇列的「重新整理」也會重新啟動外部 watcher。

### 兩種上傳擺法

**A. 子資料夾（建議）**

```
inbox/
  C302-2025F/                  ← classId
    E20250107/                 ← assignmentId
      S07__20261119T143012__001.jpg
      S07__20261119T143012__001.json   ← 可選 sidecar
```

沒有 sidecar 時，座號會從檔名解析，班級與作業由資料夾決定。

**B. 扁平**

```
inbox/
  S07__20261119T143012__001.jpg
  S07__20261119T143012__001.json
```

扁平模式**一定要有 sidecar**，由 sidecar 的 `class_id`／`assignment_id` 路由；沒有 sidecar 會移到 `_unmatched`。

### 檔名與座號規則

- 有 sidecar：使用 sidecar 的 `seat`，並驗證 `class_id`／`assignment_id`。子資料夾模式下，sidecar 必須與所在資料夾的班級、作業一致，指向錯誤會被擋下。
- 沒有 sidecar：只接受 `S07…`、`S07_…`、`S07-…`、`S07 …`，或檔名開頭正好是 `07`。
- `7`、`S7`、`S072`、沒有座號的檔名都**不猜**，直接移到 `_unmatched`。
- 支援 `.jpg`、`.jpeg`、`.png`。
- **不支援 PDF**：偵測到 PDF 會移到 `_unmatched`，原因為「目前不支援 PDF，請上傳 JPG／PNG」。
- Google Drive 衝突副本（例如 `S07 (1).jpg`）會靠 SHA-256 去重，不會重複建立頁面。

### sidecar 範例

```json
{
  "schema_version": 1,
  "class_id": "C302-2025F",
  "assignment_id": "E20250107",
  "seat": "07",
  "seq": 1,
  "session_id": "20261119T143012",
  "captured_at": "2026-11-19T14:30:12+08:00"
}
```

### 匯入、清理與失敗處理

- **成功**：圖片經轉正、移除中繼資料、產生縮圖後寫入本機 `work.json`，隨即在 Google Drive 資料夾刪除來源圖片與 sidecar，作品不長期留在雲端。
- **重複檔**：不新增頁面，移到外部根目錄的 `_duplicates/`，旁邊附 `.reason.txt`，方便老師確認。
- **失敗**：sidecar 格式錯誤、指向錯誤班級／作業、座號不在名單、圖片處理失敗、無法路由，都會移到外部根目錄的 `_unmatched/`，並附 `.reason.txt`。
- 圖片與 sidecar 可能先後到達，程式會等待約 2.5 秒 grace，不會立刻判定缺檔。
- Google Drive 同步造成暫時 0 byte 或檔案鎖定時，圖片處理會重試 2 次才移到 `_unmatched`。
- 外部根目錄不存在或無法讀取時，會顯示錯誤事件與 UI 提示，程式不會崩潰。

### 隱私注意

- Google Drive 只用來搬「上傳中的圖片」，資料庫資料夾不要放在即時同步雲端。
- 成功匯入後會刪除雲端來源，但 Google Drive 的版本紀錄與垃圾桶仍可能保留一段時間；若照片敏感，請自行到雲端清理垃圾桶與版本紀錄。
- 程式不會把學生姓名、總評或批注內容寫進日誌。

## 5.2 未匹配照片手動分配座號

### 什麼時候會出現未匹配照片

圖片沒有被自動匯入時，會留在失敗資料夾：

- 本機：`<資料庫>/<classId>/<assignmentId>/_inbox/_unmatched/`
- Google Drive：外部 inbox 根目錄下的 `_unmatched/`（全域，不分子資料夾）

常見原因包括：缺少 sidecar、sidecar 格式錯誤、sidecar 指向其他班級／作業、座號不在在學名單、檔名沒有座號、PDF 不支援、圖片處理失敗。每個檔案旁會有 `.reason.txt` 記錄原因；新版程式也會寫一份 `.meta.json`，保存已知的班級、作業、座號、來源與移動時間。

沒有 `.meta.json` 的舊檔案仍會列出，作業欄顯示「未指定作業」，不會被忽略。

### 開啟與預覽

1. 選班級與作業後，在匯入佇列按「未匹配照片」。
2. 面板會列出目前作業的內部 `_unmatched`，以及 Google Drive 根目錄 `_unmatched` 的全部圖片。
3. 每張卡片顯示縮圖、顯示名稱（已去掉時間戳前綴）、來源（本機／Drive）、失敗原因、作業資訊、修改時間與檔案大小。
4. 縮圖由主程式逐張產生 320px 預覽，不會把原始大圖一次載入畫面。

### 多選與排序

- 逐張勾選，或按「全選」「清除選取」。
- 清單依修改時間排序，時間相同時再依檔名排序；指定時也採同一順序。
- 多頁照片請確認檔名或檔案時間符合實際頁序，程式會依這個順序附加為下一頁。

### 指定給學生

1. 在「指定給」下拉選單選擇在學學生（顯示座號＋姓名）。
2. 確認面板下方文字，例如「會附加到 S07 王小明，並依檔案時間排序；複製成功後來源會刪除。」
3. 按「指定給 S07 王小明 並排入匯入」。

按下後程式會：

- 檢查班級、作業與座號是否有效，且所選路徑都位於允許的 `_unmatched` 內。
- 依序把圖片複製到該作業的 `_inbox`，並產生同名 sidecar。
- 由既有 watcher 完成轉正、去重、前處理與寫入 `work.json`。
- 成功複製後刪除原本的 `_unmatched` 圖片、`.reason.txt`、`.meta.json` 與同名 sidecar。

畫面會顯示「已排入匯入佇列」，作品佇列的頁數稍後會自動更新。

### 重要限制

- **沒有復原功能**：來源在排入後會刪除，指定前請確認學生與頁序。
- 指定後不能再用同一張來源重複指定。
- 重複照片仍由 SHA-256 去重，不會新增頁面；重複檔會依既有流程移到 `_duplicates/`。
- 指定只影響目前選取作業的內部 `_unmatched`；Google Drive 的清單是全域的，會依 `.meta.json` 顯示原本的班級與作業。沒有 meta 的 Drive 舊檔仍可手動指定給目前作業。
- 若同一次選取很多張，程式會逐張等待 watcher 消化後再放下一張，以維持頁面順序，因此可能需要幾秒。

## 6. 批閱與快捷鍵

在匯入佇列按某份作品的「批閱」，進入三欄式介面：

- 左欄：同作業其他作品，可直接切換。
- 中欄：頁面畫布。
- 右欄：批注編輯、評分、總評。

### 畫布操作

- 滑鼠滾輪：縮放。
- 拖曳：平移。
- 點畫布空白處：新增批注定位點。
- PageUp／PageDown：上一頁／下一頁。

### 快捷鍵

| 按鍵 | 功能 |
|---|---|
| `1` | 切換為「錯字」批注 |
| `2` | 切換為「語句」批注 |
| `3` | 切換為「結構」批注 |
| `4` | 切換為「佳句」批注 |
| `5` | 切換為「評語」批注 |
| `PageUp` / `PageDown` | 翻頁 |
| `Ctrl+Z` | 復原批注操作 |
| `Ctrl+Y` 或 `Ctrl+Shift+Z` | 重做 |

在輸入框、下拉選單或總評欄位打字時，數字鍵與復原鍵會保留給文字輸入，不會觸發批注快捷鍵。

### 批注與評語庫

- 五類固定批注：錯字、語句、結構、佳句、評語；另有「其他」。
- 錯字可填「錯字 → 正確字」，會用於回饋單與 G2 常錯字統計。
- 語句可選子類（不通順、語序、用詞、冗贅、語意不清、銜接、口語化、文白夾雜）。
- 右側可從內建評語庫插入常用評語；插入後仍可修改文字。
- 評語庫面板的「版本」可選「自動（依學制）」、「國中版」或「高中職版」。預設自動：國中班級用國中版，
  高中職與職業類科用高中職版；手動切換會立即重新載入清單，但不會影響目前批注、分數或已插入文字。
- 面板會顯示目前版本與 `library_version`；國中版另顯示「草稿」標籤與
  「國中版為草稿，建議校閱後使用」。要回到高中職版，選「自動（依學制）」或「高中職版」。
- 版本偏好會儲存在 `settings.json`，重開程式仍保留；切換只影響評語清單，不會改寫作品內容。
- 評語庫可依「預設」、「常用（累計）」或「本批未用優先」排序；每條會顯示本批與累計使用次數。
  按「釘選」可固定在清單最前面，再按「已釘選」取消；釘選條目在三種排序都會先排，
  釘選內依累計次數由高到低，同次數保持原順序。
- 釘選與排序是全域偏好，跨作業保留，重開程式仍有效；切換國中／高中職時只顯示目前版本的條目，
  另一版本的釘選會留在設定中，切回時繼續生效。
- 需要平均輪替時可選「冷卻輪替（久未用優先）」：從未使用或超過冷卻天數沒用的評語會先顯示，
  其餘依上次使用時間由舊到新。冷卻天數預設 30 天，可在面板調整 1–365 天；
  冷卻群內從未使用排最前，同時間再依累計次數由少到多。
- 「上次使用」不是另存的欄位，而是由作品紀錄推導：批注取該則的建立時間，總評取作品的更新時間，
  同一條評語取最新的一次；缺少時間或格式錯誤會視為從未使用。
- 釘選條目在冷卻輪替時仍固定在最前面，行為與其他排序相同。
- 冷卻輪替只改變評語清單的顯示順序，不會改寫已插入的評語、批注、分數或自動儲存的內容。
- 需要暫時隱藏不常用的評語時，按面板右上角的「管理」，每條旁會出現「停用」；
  再按「完成管理」回到一般瀏覽。停用只是把條目從日常清單隱藏，**不會刪除評語**，
  也不會改寫任何作品；面板會提示「停用不會刪除評語，舊批注仍保留文字。」
- 管理關閉時，停用條目不會出現在清單；開啟管理後才會以淡化樣式顯示，
  並標上「已停用」與「啟用」按鈕。停用期間該條無法插入，重新按「啟用」即可恢復。
- 已經插入作品或完成批閱的舊批注，保存的是當時的文字與來源；之後停用或啟用該條，
  舊作品的總評、批注文字與來源都維持原樣，不會跟著消失或被替換。
- 國中版與高中職版的停用清單分開保存；切換版本時只會看到該版本自己的停用狀態，
  另一版本的設定會留著，切回時繼續生效。停用清單重開程式仍保留。
- 需要新增自己的評語時，先按「管理」，再按「新增評語」。表單可選類別與子類、輸入評語文字與標籤；
  標籤用逗號、頓號或半形逗號分隔。總評（comment）類至少 30 字，其餘類別不設下限。
- 儲存後自訂評語會出現在目前版本的清單，並標上「自訂」。按「編輯」可修改文字與標籤，
  按「刪除」會先確認；刪除只移除評語庫條目，不會改寫任何作品。
- 自訂評語存在目前資料庫的 `_library/junior.json` 或 `_library/senior.json`，
  依版本分開；切換資料庫時各自獨立，不會寫入 `settings.json`。
- 內建評語不能刪除或修改，只能停用；刪除內建 id 會被拒絕並提示改用停用。
- 自訂評語同樣可以停用／啟用、插入與計入使用次數。已經插入作品或完成批閱的舊批注，
  保存的是當下的文字與 `library_id`；之後刪除或修改該自訂評語，舊作品的內容仍維持原樣。
- 空文字、comment 少於 30 字、非法類別／子類、與內建或自訂評語重複的文字，以及不存在的 id，
  儲存時都會被拒絕，表單會顯示錯誤訊息。
- 使用次數只讀作品紀錄中的評語來源，不另維護計數器：本批只算目前作業，累計算同班所有作業。
  從評語庫插入時會記下來源；手動改寫文字後，該則評語不再計入原本的來源。
- 修改會在約 600ms 後自動儲存；完成批閱後會自動載入下一份待批作品。

## 7. 評分與量規

### 三組預設量規

| 量規 | 內容 | 結構 | 語言 |
|---|---:|---:|---:|
| 均衡版（預設） | 40 | 30 | 30 |
| 內容導向 | 45 | 25 | 30 |
| 語言導向 | 35 | 30 | 35 |

- 分項合計必須是 100。
- 錯字與標點扣分預設各 0.5 分，上限 10 分。
- 等第門檻可在批閱前調整；門檻由高到低排序，最低分不可重複。

### 調整量規

1. 進入批閱後、評分前，按「調整量規」。
2. 可改 preset、自訂分項配分、新增／刪除等第並修改名稱與最低分。
3. 儲存時會驗證：分項合計 100、等第至少一筆、名稱不可空白或重複、最低分 0–100 且不可重複。

注意：

- 變更量規**不會自動改寫已儲存的分數與等第**。
- 目前這份作品的預覽會用新量規重算，完成批閱時才寫入。
- 若作業已有評分，調整前會先確認。

### 總評規則

- 總評至少 30 字（去空白與標點後計算）。
- 同一作業、同一批作品，完全相同（正規化後）的總評最多重複 2 次；第 3 次會阻擋。
- 完成批閱前會檢查未評分、總評不足等問題。

## 8. 回饋單列印與 PDF

作品標為「已批」後：

- 匯入佇列該列會出現「回饋單」。
- 批閱畫面右下角也有「回饋單」按鈕。

預覽視窗提供：

- **列印**：交給系統印表機。
- **匯出 PDF**：固定存到 `S{座號}/S{座號}_feedback.pdf`。
- **另存 PDF**：預設中文檔名，例如 `高中302_我的母親_S07_王小明_回饋單_2026-11-19.pdf`。

回饋單是一頁 A4，只印分數、等第、扣分、分項、總評、詞句改寫、常錯字與佳句，**不印原始作文圖**。內容過長時會自動縮小字級；仍放不下會阻擋匯出並提示縮短總評或減少批注。

### 整班批次回饋單

在匯入佇列按「批次回饋單」，面板會顯示目前作業的已批份數、未完成份數與預估輸出位置。

- 按「開始批次輸出」後，程式依座號逐份處理，只輸出狀態為「已批」且已有分數的作品。
- `pending`、`grading`、已批但未評分會列為「跳過」，原因會寫在報告，不會中斷整批。
- 單份內容超過一頁或其他錯誤會列為「失敗」，同樣繼續處理下一份。
- 輸出期間會顯示進度條、目前座號與姓名；按「取消」會在下一份開始前停止，已完成的不受影響，其餘標為「已取消」。
- 同一時間只允許一個批次；重複啟動會被拒絕。

每份成功作品會保留原本的 `S{座號}/S{座號}_feedback.pdf`，並另外複製一份到該作業資料夾的 `_feedback/`，使用中文檔名 `S{座號}_{姓名}_回饋單.pdf`；姓名空白時為 `S{座號}_回饋單.pdf`，Windows 不接受的字元會換成底線。

批次報告固定寫在 `_feedback/`：

- `report.json`：產生時間、總數、成功／跳過／失敗／取消數量，以及每筆座號、姓名、狀態、輸出路徑、原因與耗時。
- `report.csv`：同上內容，UTF-8 BOM＋CRLF，可直接用 Excel 開啟。

重跑批次會覆蓋同名 PDF 與兩份報告，不會動到原始作品、批注或圖片。列印時可開啟 `_feedback/`，全選 PDF 後一次送印；大量輸出建議先確認已批份數，分批列印以免一次占滿印表機佇列。

## 9. 統計與 CSV

在匯入佇列按「統計」，可看：

- 班級分數摘要：平均、中位數、最高、最低。
- 等第分布。
- 分項平均。
- **G1 弱項排行**：依批注類型／子類統計佔比與涉及人數。

- **G3 每人弱項**：每位學生前三弱項。

- `scores.csv`
- `weakness-ranking.csv`
- `common-typos.csv`
- `student-weakness.csv`

皆為 UTF-8 BOM＋CRLF，可直接用 Excel 開啟；重複匯出會覆寫同名檔。

## 9.1 與上次比較（G4）

同一班級可以把目前作業和另一份作業比較，看出成績與弱項類別的進步／退步。

1. 在匯入佇列按「統計」載入目前作業。
2. 在「與上次比較（G4）」下拉選上次作業。預設會選「依作業 id 由小到大排序後，目前作業之前最近的一份」；同一天撞名的 `-02` 也會正確排序。
3. 若這個班級只有目前這份作業，會顯示「這是第一份作業，尚無可比較資料」。

比較規則：

- 一律用**座號**對齊，不會用姓名猜。
- 班級平均只計「兩邊都有已批分數」的學生（已比較人數）；新作品與缺資料不列入平均，避免新作品或缺考造成假進步／假退步。
- 狀態：**進步**、**退步**、**持平**、**新作品**（上次沒有分數、本次有）、**缺資料**（上次有分數、本次沒有）；兩邊都沒有分數列為**資料不足**。
- 弱項只比**錯字、語句、結構、其他**四類，使用每位學生的批注次數，除以已比較人數，得到「每份平均次數」。Δ 為「本次－上次」：負值代表變少（改善），正值代表變多（退步）。
- 可隨時改選其他上次作業，結果會重新計算；切換目前作業時，比較選擇會重置為該作業的預設上次作業。
- 進步前 5／退步前 5 依 Δ 排序，Δ 相同時依座號排序。

## 9.2 成績寫回 Excel

適合老師已經有一份自己的成績表，只想把作文分數與等第填進去。

### 設定成績表

1. 選好班級與作業，在匯入佇列按「成績寫回」。
2. 按「選擇成績表」，選一個 `.xlsx`。程式在 main 程序讀取，不會把整份成績表載入畫面。
3. 選檔後會列出工作表、前幾列預覽，並自動建議欄位；也可以切換工作表或手動修改。
4. 確認後按「儲存設定」。設定會存在該作業資料夾的 `gradebook.json`，切換作業會各自載入。

「自動偵測」會在前 10 列找表頭：

| 用途 | 辨識規則 | 必填 |
|---|---|---|
| 表頭列 | 同時找到「座號」的列 | 是 |
| 座號欄 | 表頭含「座號」 | 是 |
| 姓名欄 | 表頭含「姓名」或「名字」 | 否 |
| 分數欄 | 表頭含「分數」「成績」「總分」「得分」；找不到時挑下方多為數字的欄 | 是 |
| 等第欄 | 表頭含「等第」「等級」「評等」 | 否 |

### 寫回規則

- 只寫 `done`（已批）且已有分數的作品；待批、批閱中列為「未完成，未寫入」。
- 用座號欄建索引，範圍是表頭下一列到工作表最後一列。
- 座號比對寬容：`7`、`07`、`S07` 都視為 `07`；**不會用姓名猜**。
- 座號在成績表找不到的作品列為「未匹配」，不寫入。
- 同一座號出現在多列時**整次中止**，報告會列出座號與所有列號，不猜哪一列才對。
- 只寫分數欄與等第欄；座號、姓名與其他欄位不動。未設定等第欄就不寫等第。
- 座號欄從表頭下一列起完全沒有可辨識座號時，會直接報錯。

### 副本與驗證

每次寫回都會先複製原檔，再對副本寫入：

```
成績.graded-20261120-153012.xlsx
```

- 副本放在原檔同一個資料夾；檔名碰撞會加 `-02`、`-03`。
- **原檔位元組完全不變**，程式從頭到尾不寫入原檔。
- 同一份作業重複寫回會產生新的 graded 副本，報告列出每筆變更前後值。
- 寫入後會重新開啟副本驗證：列數不變、每一列分數與等第正確、座號與姓名未被改。
- 驗證失敗會刪除該副本（不留下半成品），並把分數匯出成 CSV。

### 圖表、樞紐與巨集檔

以下情況不直接改原檔，改走「匯出新檔」模式：

- 副檔名為 `.xlsm`、`.xltm`、`.xlsb`、`.xls`。
- `.xlsx` 內偵測到 `xl/charts/`、`xl/pivotTables/`、`xl/pivotCache/`、`vbaProject.bin`。

匯出模式會在原檔旁建立乾淨的 `.xlsx`，包含表頭「座號、姓名、分數、等第」與所有已批作品；原檔不變。報告會標示模式與原因。

### 失敗與 CSV

任何失敗（檔案鎖住、工作表不存在、欄位格式錯、座號重複、沒有可寫作品、權限不足、驗證失敗）都會：

1. 顯示繁體中文原因。
2. 在作業資料夾的 `_gradebook/` 匯出 `grades-YYYYMMDD-HHmmss.csv`，至少含座號、姓名、分數、等第、狀態。
3. 在報告顯示 CSV 路徑。

也可以隨時按「匯出 CSV」手動產生；UTF-8 BOM＋CRLF，Excel 可直接開。

### 常見錯誤

- **檔案被其他程式鎖定**：通常是 Excel 開著。請先關閉 Excel；程式會自動重試 2 次。
- **座號對不到**：確認成績表的座號欄與表頭列是否正確，以及該列是否為空白或含其他文字。程式不接受用姓名配對。
- **座號重複**：同一座號出現兩列以上。請先在 Excel 刪除或修正重複列，再重新寫回。
- **找不到工作表**：Excel 改過工作表名稱，或設定指到別份檔案。重新選擇並儲存設定。
- **權限不足**：成績表或輸出資料夾在唯讀位置。請改放可寫入資料夾，或關閉唯讀。

## 9.3 佳句庫（G6）

右上角「佳句庫」會把班級與作業裡標成「佳句」的批注收集起來，方便跨作業累積可用句、日後講評或出練習。開啟後是覆蓋式面板：

- **範圍**：預設「本班」，只掃目前班級的所有作業；按「全部班級」會掃描資料庫內所有班級。尚未選班級時只顯示全部班級。
- **搜尋**：輸入關鍵字即時篩選佳句原文（不分大小寫、比對字串）。
- **清單**：每筆顯示佳句原文、使用次數、出現的作品份數與來源作業名稱；同名佳句會合併。
- **複製**：每筆右側有「複製」；也有「複製全部篩選結果」，會以空行分隔放入剪貼簿。程式只在你按下按鈕時寫入剪貼簿，不會自動讀取或覆寫既有內容。
- **排序**：使用次數多到少；同次數時，最後使用時間新到舊。

收錄規則：

1. **只收已完成作品**：狀態為「已批」的 `done` 作品才會納入；待批（`pending`）與批閱中（`grading`）的佳句不會提前出現在佳句庫。
2. **只收佳句類別**：只有「佳句」批注會收；語句、結構、錯字、評語與其他類別都不列入。
3. **去重**：比對前會去除空白、標點與 `{變數}`；同一句即使標點或空格不同也會合併，原文保留第一次出現的版本。
4. **時間**：優先使用批注的建立時間；缺少時退回作品的儲存時間，用來顯示最早與最後使用時間。

隱私與資料：

- 佳句庫輸出**不含學生座號、姓名或任何學生識別欄位**，只保留佳句原文、次數、作品份數與來源作業名稱。
- 功能是**只讀**：不會新增、修改或刪除任何 `work.json`、分數或批注。
- 所有處理都在本機完成，不連網、不上傳；複製的內容只會留在你自己的剪貼簿。
- 讀不到的作業（例如 `assignment.json` 損壞）會被跳過並記入日誌，不會讓整個佳句庫失敗；損壞的 `work.json` 同樣略過。

## 10. 備份與還原

### 備份

1. 開啟資料庫後，按右上角「備份資料庫」。
2. 選儲存位置；預設檔名為 `essay-grader-backup-YYYYMMDD-HHmm.zip`。
3. 完成後會提示備份檔數與大小。

備份內容是**整個資料庫根目錄的相對路徑**，包含：

- 班級 `class.json`
- 作業 `assignment.json`
- 學生 `work.json`
- 頁面圖片、縮圖
- `_stats/` CSV
- 原子寫入留下的 `.bak`

備份會排除：

- `.essay-grader.lock`
- 所有 `*.tmp`（含 `*.restore.tmp`）

zip 內不會出現磁碟代號或絕對路徑。備份檔名不含學生姓名。

### 還原

1. 按「還原備份」。
2. 選 zip。
3. 選一個**新的空資料夾**。
4. 程式解壓後會直接以新資料夾開啟資料庫。

安全規則：

- 目的地不是空資料夾 → 直接拒絕，不會覆寫。
- 不能還原到目前開啟的資料庫、它的子資料夾或上層資料夾。
- 會先檢查 zip 內所有路徑；含絕對路徑、磁碟代號、`..`、符號連結或重複路徑一律拒絕（zip slip 防護）。
- 若 zip 含檔案但沒有 `class.json`，會視為「不是作文批閱資料庫」並停止。
- 解壓失敗時會清掉這次寫入的內容，不會留下半套資料。

還原成功後，舊資料庫仍原封不動；確認新資料庫無誤再決定是否刪除舊的。

### 建議節奏

- 每次大批匯入或批完一個作業後備份一次。
- 學期末把備份 zip 另存到雲端或外接硬碟。
- 備份 zip 與資料庫資料夾不要放在同一個即時同步資料夾。

## 11. M: 固定磁碟腳本

專案路徑約定為 `M:\dev\projects\essay-grader`。若把專案磁碟接到新主機後拿到其他代號：

1. 關閉所有使用該磁碟的程式與終端機。
2. 以**系統管理員**開啟 PowerShell。
3. 在專案資料夾執行：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\fix-m-drive.ps1
```

腳本會把專案所在磁碟區改成 `M:`：

- 已在 `M:` 時不變更。
- `M:` 已被其他磁碟占用時會停止並提示先釋放。
- 變更磁碟代號需要系統管理員權限；完成後重新開啟終端機與編輯器。

這個腳本只影響開發環境；一般使用者不需要執行。

## 12. 日誌位置與回報問題

按右上角「開啟日誌」會開啟日誌資料夾。預設位置：

```
%APPDATA%\作文批閱\logs\app.log
```

- 每筆含 ISO 時間、level（INFO／WARN／ERROR）與訊息。
- `app.log` 超過約 2 MB 會輪替為 `app.1.log`，避免無限成長。
- 主程序未捕捉的錯誤、未處理的 Promise rejection、畫面程序結束、載入失敗都會寫入。
- React 畫面發生錯誤時會顯示友善錯誤畫面，可重新載入或開啟日誌，不會只剩空白視窗。

隱私原則：日誌只記錄**事件與錯誤訊息**，不記錄學生姓名、總評全文、批注全文或圖片內容。回報問題時可提供 `app.log` 與 `app.1.log`；若仍擔心，可先自行開啟確認。

## 13. 隱私與資料安全

- 不連網、不上傳、不埋 telemetry。
- 資料庫是普通資料夾，可自行用檔案總管備份、複製、壓縮。
- 匯入圖片時會轉正、移除 GPS／中繼資料並產生縮圖。
- 回饋單與統計只寫在本機資料庫資料夾。
- 日誌不含學生姓名、總評、批注全文或圖片內容。
- Google Drive 外部 inbox 只用來接收手機上傳的圖片；資料庫、`work.json`、分數與總評都不進雲端。成功匯入後會刪除雲端來源，但雲端版本紀錄與垃圾桶可能仍保留一段時間。
- 程式沒有學生帳號、沒有雲端同步資料庫、沒有 AI 評分。

## 14. 常見問題

### Q：開啟資料庫時說「資料庫已被其他程式開啟」

先關閉另一個作文批閱視窗或 portable 版本。若確定沒有其他程式，可能是上次異常關閉留下鎖檔；同機且程序已結束時會自動接手。仍無法開啟時，確認 `.essay-grader.lock` 的電腦名稱是不是別台電腦（例如資料庫放在共用磁碟）。

### Q：還原時說「目的地不是空資料夾」

程式不覆寫既有資料。請新建一個空資料夾，或把原本資料夾裡的東西先移到別處。也不要選目前資料庫或其子資料夾。

### Q：還原時說「這個 zip 看起來不是作文批閱資料庫備份」

zip 內沒有任何 `class.json`。請確認選到正確的備份檔，而不是一般壓縮檔或圖片包。

### Q：Excel 名單匯入後人數不對

程式只新增與更新，不會刪除舊名單。請檢查 Excel 的座號欄是否被辨識為文字或數字、姓名是否空白；結果提示會列出跳過的列。也可以在名單表格手動修正後按「儲存名單」。

### Q：inbox 的檔案沒有進來

檢查：

1. 圖片與 sidecar 是否同主檔名。
2. sidecar 的 `class_id`、`assignment_id`、`seat` 是否正確。
3. 座號是否在名單中且在學。
4. 檔案是否被移到 `_unmatched`（原因會寫在旁邊或匯入狀態）。

### Q：Google Drive 上傳後桌機沒有反應

1. 確認已安裝並登入 Google Drive for desktop，且本機同步資料夾存在。
2. 在「Google Drive inbox」區塊確認路徑正確、狀態為「監看中」；必要時按「重新整理」。
3. 扁平模式一定要有 sidecar；子資料夾模式若沒有 sidecar，檔名必須以 `S07` 或 `07` 開頭。
4. PDF 不支援，請上傳 JPG／PNG。
5. 失敗檔會出現在外部根目錄的 `_unmatched/`，打開旁邊的 `.reason.txt` 查看原因。

### Q：照片在 `_unmatched`，要怎麼重新分配座號？

在匯入佇列按「未匹配照片」，勾選照片、選擇在學學生，再按「指定給 S07 王小明 並排入匯入」。程式會把照片複製到該作業的 `_inbox` 並產生 sidecar，由 watcher 附加為下一頁；成功排入後會刪除 `_unmatched` 來源，沒有復原功能。重複照片仍會去重，不會多一頁。

### Q：回饋單無法匯出 PDF

通常是內容超過一頁 A4。請縮短總評、減少批注，或降低批注字數；程式會自動降到最小字級，仍放不下才阻擋。

### Q：批次回饋單有幾份被跳過或失敗

`_feedback/report.json` 與 `report.csv` 會逐筆列出原因。未完成批閱或尚未評分會跳過；內容超過一頁會失敗，但不影響其他份。修正該份後可重跑整批，同名 PDF 與報告會覆蓋。

### Q：批次回饋單要怎麼列印

開啟作業資料夾的 `_feedback/`，全選 PDF 後按右鍵列印。份數多時建議分批列印，避免印表機佇列過長；個別檔案仍保留在 `S{座號}/`。

### Q：統計數字和想像不同

統計只計 `done` 作品；`pending`、`grading`、未匯入都不計入班級數字。G1 以「弱項批注總數」為分母，佳句不列入弱項。CSV 的個人表仍會列出未計入的學生。G4 比較的平均只以「兩邊都有已批分數」的學生計算，新作品與缺資料不會拉高或拉低平均。

### Q：換電腦後資料怎麼搬？

複製整個資料庫資料夾，或在新電腦用「還原備份」。還原一定要選新的空資料夾。程式設定與日誌不需要搬。

### Q：可以同時開兩個視窗批閱嗎？

不行。程式限制單一實例，且資料庫有鎖，避免兩個 writer 同時寫入。

### Q：portable 版放在隨身碟，資料會存在隨身碟嗎？

不會。資料庫位置由你第一次開啟時選擇；程式設定與日誌在使用者資料夾。若要把資料帶著走，請把資料庫資料夾也放在隨身碟，並在每台電腦重新「開啟資料庫」指向它。

## 15. 目前版本限制（0.1.0）

- 只支援 Windows x64；尚無 macOS／Linux 安裝檔。
- 整班批次回饋單會逐份開啟隱藏視窗，份數多時需要一些時間；批次期間請避免同時操作同一份作品。
- 成績寫回以單一作業、單一工作表為範圍；ExcelJS 可能微調樣式（字型、欄寬、圖表），因此含圖表／樞紐／巨集的檔案一律改走匯出新檔，不直接改原檔。
- 已提供 Google Drive 本機同步資料夾作為外部 inbox；手機端 App（M8）尚未實作，目前可用手機的 Google Drive App 手動上傳照片與 sidecar。
- 外部 inbox 只支援 JPG／JPEG／PNG，PDF 會進 `_unmatched`。
- 外部 inbox 依賴 Google Drive for desktop 的本機同步；未安裝或未登入時無法使用。
- 未匹配照片可手動指定座號，但沒有復原功能；指定後來源會刪除，重複照片仍靠 SHA-256 去重。
- 未匹配照片一次只處理目前作業的內部 `_unmatched`；Google Drive 的 `_unmatched` 為全域清單，會依 meta 顯示原作業。
- 內建評語庫同時包含國中版與高中職版，預設依班級學制自動選用，也可在批閱畫面手動切換；
  國中版仍是草稿（`2026.2-draft`），建議校閱後使用。
- 評語庫使用次數只計有 `library_id` 的作品；較早期、未記錄來源或手動改寫過的評語不列入，
  因此「累計」可能低於實際使用感覺。累計需掃描同班所有作業，作品很多時面板會先顯示統計中。
- 冷卻輪替的最後使用時間同樣只看 `library_id`；沒有來源的舊批注不列入，缺少或錯誤的時間視為從未使用。
  總評的時間用作品更新時間推算，因此之後修改同一份作品會讓該條總評看起來較新。
- 停用評語只影響目前版本的清單顯示，不會刪除內建條目；已批作品的批注與總評是當時的快照，
  停用或重新啟用都不會改寫，若要更換內容仍需在該份作品手動改寫。
- 量規三組數值與等第門檻仍是預設值，建議依學校需求調整。
- 統計與 G4 比較以單一作業對單一作業為範圍，尚無題目間整體比較（G5）或全年級趨勢。
- 已提供 `npm run soak` 連續 10 分鐘壓力測試（45 人、每圈 45 份回饋單）；測試涵蓋批次輸出、批次檢查、統計與 autosave，未同時模擬實際批閱 UI 與匯入 watcher 的並行負載。
